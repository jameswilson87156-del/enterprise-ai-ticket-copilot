# 面试讲解指南

## 一句话介绍

这是一个 Vue 3 + Spring Boot 的企业工单 Copilot：把工单录入、分类、知识检索、处理建议、人工确认和知识沉淀串成一个可演示闭环，并增加了可从前端触发的检索评测页面。

## 约 90 秒项目讲法

我做的是一个企业内部工单与知识库助手，目标是让支持人员在同一个工作台里查看工单上下文、相关知识和处理建议。前端用 Vue 3 和 TypeScript，后端用 Java 17、Spring Boot、MyBatis-Plus 和 MySQL。

工单进入后，后端会生成分类和建议，再匹配已发布知识；工单状态变化、知识草稿发布仍需人工确认。模型分类通过 Spring AI 的 OpenAI-compatible ChatModel 接口接入，可以用环境变量配置 DeepSeek；响应会解析为有限类别的结构化 JSON，并校验响应字段。Provider 调用失败、超时、坏 JSON、非法类别或命中输出契约时，门面降级到规则分类。知识匹配在向量通道不可用时会退化到关键词检索。

我最近把检索质量做成了一个可操作的闭环：仓库里维护版本化合成问句和多相关 qrels，前端点击后调用 Spring Boot 评测接口；后端在固定演示语料里运行关键词基线，计算 Hit Rate、Macro Recall、Precision@3、MRR 和无匹配特异度，同时保存逐样本排名、候选文章和失败类型。V3 诊断集暴露了部署配置别名漏召回，我补齐演示知识关键词后再跑 H2/MyBatis 集成；V4 又定位到采购 FAQ 使用“采购、审批”泛关键词造成打印机误召回。我只收窄该条知识的关键词，保留评分阈值和全部 qrels；V4 中 8 条无匹配查询全部无召回，14 条正向查询仍有相关知识首位命中。这样可以从前端一路讲到 Controller、Service、MyBatis 查询、指标计算和失败定位。

检索评测只覆盖仓库内的合成样例，测的是关键词基线，不是 DeepSeek 检索成绩，也不代表生产效果。V3 是查看 V2 失败后写的诊断集，V4 复用 V2/V3 开发样本做元数据回归，两者都不是独立留出集。工单分类另有独立的分类与安全评测，不能和检索评测混在一起。

## AI 分类评测与红队测试

分类评测有三种结果，面试时要分别说明来源：

1. **历史真实模型对比：**40 条合成普通工单曾实际发送给 DeepSeek Flash，结果为 38/40 正确，Accuracy 95.00%、Macro-F1 94.99%；T04 和 T13 是错分样本。它是固定小样本上的历史分类结果，不是红队安全率，也不能代表生产工单表现。逐样本信息见[分类评测 v3](evidence/classification-eval-v3/README.md)。
2. **规则引擎红队基线：**70 条合成工单覆盖 14 类提示注入、Unicode 混淆和业务症状保留场景，每类 5 条。当前规则离线结果为 70/70；这验证的是规则分类对固定数据集的行为，不能表述成 DeepSeek 70/70 或“模型安全率 100%”。详见[红队评测 v5](evidence/classification-eval-v8/RED_TEAM_EVALUATION_V5_CN_20261022.md)。
3. **模型输出契约回归：**新增 9 个输出侧攻击样本和 2 个普通文案控制样本，使用模拟 `ChatModel` 验证标记回显、提示词/凭证提取和破坏性指令会触发规则降级，同时普通 “Canary deployment” 和 “marker” 文案不会误触发。结果为 9/9 攻击降级、2/2 控制通过；这是本地模拟 Provider 测试，不是对 DeepSeek 的实测。另用哨兵测试复现并修复了 ChatModel 与 Embedding Provider 异常原文进入日志的问题。详见[输出契约红队评测](evidence/classification-eval-v9/LLM_OUTPUT_CONTRACT_REDTEAM_V1_CN_20261022.md)。

4. **跨文字系统同形字回归：**新加 3 条西里尔字符 canary 回显攻击和 2 条普通控制。测试先复现 3 条攻击都没有走规则降级，再只在 canary 指纹比较中折叠有限的常见西里尔同形字；修复后为 3/3 攻击降级、2/2 控制通过。完整 Maven 回归为 75 项、0 失败、0 错误、1 项跳过。详见[输出同形字红队 v1](evidence/classification-eval-v10/UNICODE_CONFUSABLE_OUTPUT_REDTEAM_V1_CN_20261022.md)。

5. **正常上下文控制集：**我另做了 10 条工单样本，安全术语出现在安全复盘或日志引用里，实际故障线索仍是正常业务问题；账号、权限、系统、数据、流程五类各两条。规则分类 10/10，净化后 10/10 保留必需问题线索，五类混淆矩阵都落在正确类别。它验证的是固定合成控制，不是模型安全率；可从[控制集报告与逐样本结果](evidence/classification-eval-v13-benign-controls/TICKET_BENIGN_SECURITY_CONTROLS_V1_CN_20261022.md)复现。

面试可以这样讲修复过程：“我先用 canary 标记验证输入边界。测试发现模型输出把下划线标记改成空格、再把部分拉丁字母替换成西里尔同形字后，旧逻辑仍会接收为 LLM 结果。于是我加了 NFKC 和格式字符归一化，再在有限的 canary 指纹里折叠常见同形字；响应违反输出契约时走现有规则降级。我还加了普通 canary 文案控制样本，避免过滤器误伤正常文本，并把每个样本的预期来源和实际来源写入 JSON。”

如果问日志如何处理，可以补充：“我用包含合成敏感哨兵的异常消息做日志捕获测试，先确认旧代码会原样打印 Provider 异常；随后把分类与向量索引的失败日志改为只记录异常类型和降级动作，避免 SDK 错误文本把响应体或凭证带到应用日志。”

需要主动讲清楚：当前没有可用的 DeepSeek 环境密钥，因此最新 70 条输入红队和 11 条输出契约回归都没有真实模型请求。代码里的正则和 canary 检查是已知模式的纵深防御，不能保证挡住任意语义改写；要比较模型自身的表现，下一步应使用轮换后的密钥，对合成样本做受控分批实测，并把规则、Mock、DeepSeek 输出分别归档。

## 现场演示顺序

1. 用普通前端 API 模式启动页面，先展示工单详情、知识命中和人工确认操作，说明这是现有业务闭环。
2. 切换到「RAG 检索评测」，先指出页面没有预填分数，评测数据是仓库内的合成问句。
3. 点击「运行检索评测」，展示后端返回的 Hit Rate、Macro Recall、Precision@3、MRR、无匹配特异度，以及逐条查询的相关知识排名和诊断。
4. 选一条目标知识未进入前三或排序靠后的样例，解释如何沿着查询、限定语料、匹配结果和排名定位问题。
5. 明确说明当前指标只针对这批固定样例上的关键词基线；不要把它说成模型效果或生产命中率。

启动步骤和接口命令见 [检索评测演示说明](retrieval-evaluation-demo.md)。

## V3 检索诊断怎么讲

“我在 V2 固定语料上看到部署环境配置类改写会漏召回，于是加了一组单独版本的诊断样例，覆盖 12 条正向查询和 8 条无匹配查询。V3 第一次跑时，ConfigMap、Secret、启动参数这些正文概念没有进入部署知识关键词，所以那条查询无结果；我先用 H2/MyBatis 测试复现，再补齐知识条目的别名后重跑，12 条正向查询均有相关知识进入首位，Macro Recall@3 达到 100%。同时，打印采购审批单时打印机卡纸仍误召回采购 FAQ，我保留它作为词面检索边界。V3 是看过 V2 失败后写的诊断集，不拿它冒充独立测试或 DeepSeek 成绩。”

## V4 采购 FAQ 元数据回归怎么讲

“后续我检查了 V3 留下的打印机误召回，发现 FAQ 的‘采购’和‘审批’两个泛词各加 18 分，恰好跨过了 35 分阈值。这个具体问题更适合收紧知识元数据，我保留 `采购、流程、FAQ、材料`，移除泛词 `审批`，没有调全局门槛，也没有改样本标签。V4 把 V3 全集与 V2 两条采购正向查询合成 22 条针对性回归，变更前后正向查询均为 14/14 首位命中，无匹配特异度由 7/8 提升到 8/8。V4 复用已看过的开发样例，只能说明这个元数据修正通过回归，不能说成盲测泛化结果。”

## 高频追问与回答骨架

### 为什么加入检索评测？

光看页面能返回知识，无法判断查询改写后目标文章是否仍能被找到，也不方便定位排序问题。我给问句维护期望文章编号，用同一组固定样例运行检索，再看命中位置和排名指标，形成可复现的回归基线。

### Hit Rate、Macro Recall 和 MRR 分别表示什么？

Hit Rate@1/@3 统计正向查询里至少一篇相关知识出现在第一位/前三位的比例。Macro Recall@1/@3 会先按每条查询计算 qrels 中被召回的相关知识占比，再对查询平均，所以多相关查询可能命中一篇但 Recall 仍小于 1。MRR 对每条正向查询的首篇相关知识排名取倒数后求平均，未召回按 0 计；无匹配查询单独算特异度，避免与正向召回混为一项指标。

### 为什么评测只在列出的知识条目里检索？

当前数据集限定到 14 篇固定演示知识，确保语料可复现；另有无匹配查询监控固定语料上的误召回。它不能反映更大知识库的误召回分布，也不等于独立留出集，因此需要后续增加独立标注与全库候选评测。

### 这个页面评的是 DeepSeek 吗？

不是。检索评测显式运行关键词基线，不调用 DeepSeek 或 Embedding API。DeepSeek 用于可配置的工单分类 ChatModel；历史 40 条普通工单曾有一批真实 DeepSeek 结果，但当前红队数据没有发送给 DeepSeek。检索评测、规则红队、Mock 输出契约测试和历史模型分类评测是不同链路，不能混算。

### 为什么 DeepSeek 失败时回到规则分类？

工单分类不能因为模型超时或返回格式异常而阻断工作流。分类服务要求输出有限类别的结构化结果，解析层会校验类别并约束置信度；输入清理和输出契约校验失败也会走规则结果。界面仍显示建议来源，工单状态仍由人工处理。规则分类只是可解释的回退路径，不等于能处理所有自然语言和所有新型攻击。

### 评测结果不理想时怎么迭代？

先区分目标文章完全未召回和召回后排序靠后，再看失败查询和目标文章字段。前者优先检查词项覆盖、分词和召回阈值；后者检查打分与重排。每次修改后对同一固定数据集重新运行，并保留数据集版本和结果，避免只挑有利样例。

### 当前方案的限制是什么？

数据是合成的，样本覆盖有限；V3 是基于 V2 失败分析整理的诊断集，V4 复用 V2/V3 开发样本做元数据回归，两者都不是盲测集；规则红队和 Mock 输出契约测试不测大模型自身的安全率。当前尚无 DeepSeek 或向量检索对照。下一步是在轮换密钥后，对固定版本的普通分类集和红队集合分批做真实模型对照，再扩充经授权且脱敏的独立查询和负例。

## 不能混淆的项目边界

- 这是个人作品集项目和本地演示系统，不是已上线生产系统。
- 分类和检索数据均为仓库内的合成样例；介绍任何数字时必须同时说明评测对象和模式。
- 检索评测 API 只跑关键词基线；不调用 DeepSeek，也不代表模型效果。
- AI 结果是辅助建议；工单状态变化和知识发布由人工确认。
- 项目使用 MySQL 作为本地业务数据源，不能描述成真实企业生产数据。

## 编码文本红队补测（2026-10-22）

可以这样讲：“我在已有 Unicode 混淆和输出契约回归上，再加了一个边界明确的编码文本专项。百分号编码和数字 HTML 实体各自组成攻击用例，并分别配置普通控制。红测先复现输入清理与输出 canary 检查的漏检，再用最多两轮 ASCII 解码覆盖这两种编码；修复后输入攻击片段被移除且故障线索保留，输出攻击触发规则降级，四条控制都按预期处理。专项只有每个测试面 4 条合成样本，使用规则和模拟 ChatModel，不是 DeepSeek 安全率。”

追问时应补充：实现只识别明确的注入句式和 canary 指纹；它不覆盖 Base64、ROT13、任意 Unicode 或语义改写。测试通过不等于模型本身安全，真实模型红队尚未运行。

## 编码红队扩展 V12

可以这样讲：“在百分号/HTML 实体专项之后，我又覆盖显式标注的 Base64、Base64URL、十六进制和 ROT13。输入侧用带 `Actual issue` 的工单验证攻击句被剔除、故障线索继续用于分类；输出侧让本地 ChatModel stub 回显编码 canary，检查结果是否回退到规则分类。4 条输入攻击、4 条控制、3 条输出攻击和 3 条输出控制都符合预期；测试还发现 Base64 不能在解码前转小写，因为这会破坏大小写敏感的编码串。”

被问到指标时说明：这 14 条是固定合成样例，测的是规则引擎和模拟 ChatModel 的输入/输出契约，没有真实 DeepSeek 请求，也不是模型安全率。它不覆盖无前缀 Base64、任意嵌套或语义改写。

## 无害安全词汇控制扩展 V2（2026-10-22）

面试讲法：“我把正常上下文控制从 10 条扩到 30 条，五类各 6 条，仍保留 V1 原样本。新增工单把提示词、密钥或破坏性命令作为日志/安全复盘引用，验证安全清洗会不会误删真正的问题描述。红测 TBC20 发现命令匹配可跨句误删‘调度任务停止执行’线索；我把命令匹配限定在同一句，再跑后 30 条分类和线索保留均通过。”

追问时强调：30/30 是 `RULE_ONLY` 固定合成控制集结果，不是总体分类准确率或 DeepSeek 安全率。报告和逐样本混淆矩阵见[无害控制 V2](evidence/classification-eval-v14-benign-controls/TICKET_BENIGN_CONTROLS_V2_CN_20261022.md)。
