# 面试讲解指南

## 一句话介绍

这是一个 Vue 3 + Spring Boot 的企业工单 Copilot：把工单录入、分类、知识检索、处理建议、人工确认和知识沉淀串成一个可演示闭环，并增加了可从前端触发的检索评测页面。

## 约 90 秒项目讲法

我做的是一个企业内部工单与知识库助手，目标是让支持人员在同一个工作台里查看工单上下文、相关知识和处理建议。前端用 Vue 3 和 TypeScript，后端用 Java 17、Spring Boot、MyBatis-Plus 和 MySQL。

工单进入后，后端会生成分类和建议，再匹配已发布知识；工单状态变化、知识草稿发布仍需人工确认。模型分类通过 Spring AI 的 OpenAI-compatible ChatModel 接口接入，可以用环境变量配置 DeepSeek；返回内容会解析成约定 JSON，类别不在允许集合或调用失败时由门面降级到规则分类。知识匹配在向量通道不可用时会退化到关键词检索。

我最近把检索质量做成了一个可操作的闭环：仓库里维护了一组带期望知识编号的合成问句，前端点击后调用 Spring Boot 评测接口；后端限定在对应评测语料里执行关键词基线检索，计算 Recall@1、Recall@3 和 MRR，同时返回每条查询的目标排名、候选文章和失败类型，并保存 JSON 报告。这样面试时可以从前端一路讲到 Controller、Service、MyBatis-Plus 查询、指标计算和失败样例。

这份评测当前只覆盖仓库内的合成样例，测的是关键词基线，不是 DeepSeek 检索成绩，也不代表生产效果。我会把它作为可重复的基准；后续再补充负例、扩充标注集，并在 Embedding 可用时比较混合检索与基线。

## 现场演示顺序

1. 用普通前端 API 模式启动页面，先展示工单详情、知识命中和人工确认操作，说明这是现有业务闭环。
2. 切换到「RAG 检索评测」，先指出页面没有预填分数，评测数据是仓库内的合成问句。
3. 点击「运行检索评测」，展示后端返回的 Recall@1、Recall@3、MRR，以及逐条查询的目标排名、候选文章和诊断。
4. 选一条目标知识未进入前三或排序靠后的样例，解释如何沿着查询、限定语料、匹配结果和排名定位问题。
5. 明确说明当前指标只针对这批固定样例上的关键词基线；不要把它说成模型效果或生产命中率。

启动步骤和接口命令见 [检索评测演示说明](retrieval-evaluation-demo.md)。

## 高频追问与回答骨架

### 为什么加入检索评测？

光看页面能返回知识，无法判断查询改写后目标文章是否仍能被找到，也不方便定位排序问题。我给问句维护期望文章编号，用同一组固定样例运行检索，再看命中位置和排名指标，形成可复现的回归基线。

### Recall@1、Recall@3 和 MRR 分别表示什么？

Recall@1 表示目标文章排第一的查询占比；Recall@3 表示目标文章进入前三的查询占比；MRR 对每条查询的目标排名取倒数后求平均，排名越靠前贡献越大，未召回按 0 计。当前只有一个期望目标文章/查询，因此这里的 Recall 是按查询统计的命中比例。

### 为什么评测只在列出的知识条目里检索？

当前数据集先限定到它覆盖的演示知识条目，确保评测语料固定、结果可复现，也避免本地额外知识改变排序。这个设计不能反映全库误召回，因此下一步需要加入无关知识和负例，并在更完整的标注语料上评估。

### 这个页面评的是 DeepSeek 吗？

不是。它显式运行关键词基线，不调用 DeepSeek 或 Embedding API。DeepSeek 用于可配置的工单分类 ChatModel；模型接入和解析失败会由分类门面降级到规则分类。检索评测与模型分类评测是两条不同链路，不能把关键词基线分数说成 DeepSeek 成绩。

### 为什么 DeepSeek 失败时回到规则分类？

工单分类不能因为模型超时或返回格式异常而阻断工作流。分类服务要求输出有限类别的结构化结果，解析层会校验类别并约束置信度；门面捕获调用或解析失败后走规则结果，界面仍显示建议来源，工单状态仍由人工处理。

### 评测结果不理想时怎么迭代？

先区分目标文章完全未召回和召回后排序靠后，再看失败查询和目标文章字段。前者优先检查词项覆盖、分词和召回阈值；后者检查打分与重排。每次修改后对同一固定数据集重新运行，并保留数据集版本和结果，避免只挑有利样例。

### 当前方案的限制是什么？

数据是合成的，样本覆盖有限，评测还限定在目标语料内；指标只反映关键词基线，没测全量知识库的误召回，也没有 DeepSeek/向量检索对照。下一步是扩充真实授权且脱敏的查询标注、增加负例，再比较关键词、向量和混合策略。

## 不能混淆的项目边界

- 这是个人作品集项目和本地演示系统，不是已上线生产系统。
- 检索评测数据是仓库合成样例；没有实际运行并留存报告前，不报评测分数。
- 检索评测 API 只跑关键词基线；不调用 DeepSeek，也不代表模型效果。
- AI 结果是辅助建议；工单状态变化和知识发布由人工确认。
- 项目使用 MySQL 作为本地业务数据源，不能描述成真实企业生产数据。
